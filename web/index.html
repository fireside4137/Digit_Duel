🔬 Engineering Story: CNN vs RNN on MNIST

The Silent Bug in RNN

When training the 2-layer RNN, accuracy initially stagnated at 84.7% with loss refusing to drop below 1.53. The root cause was an accidental torch.sigmoid() applied to the logits right before CrossEntropyLoss. Because PyTorch's cross-entropy loss already applies log_softmax, sigmoiding the logits severely restricted gradients. Removing that single line instantly unlocked proper convergence: loss plummeted to 0.108 and accuracy leaped to 97.0%!

Why Center-of-Mass Centering Matters

If you feed a naive 28×28 resize of a user's drawing to MNIST models, accuracy plummets to ~40%. Real MNIST digits are tightly bounded in a 20×20 box, scaled by aspect ratio, and translated so their center of mass sits exactly at pixel (13.5, 13.5). This web app implements that exact algorithm on the fly.

Zero-Sleep Deployment with ONNX

Instead of hosting heavy Python servers on Streamlit or Render that go to sleep after minutes of inactivity, we exported the PyTorch weights to an optimized 1.5 MB ONNX model. Inference runs natively inside your browser's WebAssembly engine in ~3 milliseconds.
